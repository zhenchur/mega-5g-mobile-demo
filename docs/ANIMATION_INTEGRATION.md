# Интеграция моушн-системы

Версия: 5 сентября 2026. Порядок переноса текущих desktop и mobile в продуктовую реализацию.

**Параметры и сценарии находятся в [MOTION_SYSTEM.md](MOTION_SYSTEM.md).** Результаты проверки — в [HANDOFF_REVIEW.md](HANDOFF_REVIEW.md). Здесь описан порядок переноса в продукт.

## Архитектура

1. Сначала собрать статическую композицию и reduced-motion режим. Порядок зон: Intro → Profiles → Lower (Connect, FAQ, Footer).
2. Условно монтировать только одну версию: mobile ≤767, tablet gate 768–1279, desktop ≥1280. Скрывать второе активное дерево через CSS недостаточно: его триггеры продолжат работать.
3. Подключить общий [cardReveal.ts](../src/motion/cardReveal.ts). Он содержит форму внешнего входа и параметры вложенного появления. Видимая карточка и неподвижный layout-slot должны быть разными узлами.
4. Сохранить уровни: **slot → rise → card → внутренние интерактивные слои**. Slot определяет триггер; rise отвечает за вертикальный перенос; card — за opacity и 3D-поворот. Изображение hover, смена вкладки и свайп не должны перезаписывать transform этих узлов.
5. Общую последовательность родителя и вложенного ряда держать в [profileCardReveal.ts](../src/motion/profileCardReveal.ts). Компоненты передают DOM-цели, порог и мобильное условие видимости ряда. [tokens.ts](../src/motion/tokens.ts) хранит параметры промо и crossfade.
6. `Lower` — только композиция отдельных Connect, FAQ и Footer. [useConnectTabs](../src/interactions/useConnectTabs.ts) владеет состоянием, клавиатурой, crossfade и измерением высоты. [bindStepSwipe](../src/interactions/stepSwipe.ts) распознаёт жест, а mobile hooks определяют движение карточек.
7. Общие CSS находятся в [src/styles](../src/styles) и подключаются через [styles.css](../src/styles.css). Стили отдельных зон расположены рядом с mobile/desktop-компонентами.
8. Добавить независимые time-based entrance, затем scroll-linked промо, затем взаимодействия. Общий master timeline страницы не нужен.

## Владение состоянием и очистка

- Создавать GSAP-анимации внутри scoped `useGSAP` / `gsap.matchMedia`; при размонтировании и смене reduced-motion выполнять revert.
- Очищать listeners, ResizeObserver, RAF, ссылки на timeline и Lenis в том же компоненте, который их создаёт. Не добавлять глобальные cleanup-вызовы, убивающие анимации соседних модулей.
- Регистрировать ScrollTrigger один раз в browser bootstrap. В демо повторная безопасная регистрация находится в компонентах.
- Desktop Lenis работает в root/window-режиме: `autoRaf:false`, GSAP ticker передаёт время в миллисекундах, событие scroll вызывает ScrollTrigger.update. На mobile работает нативный скролл.
- Вызывать ScrollTrigger.refresh после готовности шрифтов и реального изменения геометрии. Не пересчитывать её на каждом кадре прокрутки. Высота мобильных вкладок обновляет пороги после завершения перехода; ResizeObserver следит за внутренними панелями.
- У `createCardReveal` начальные и конечные значения постоянны, поэтому `invalidateOnRefresh` отключён внутри примитива и исключён из его options. Refresh продолжает пересчитывать start/end без повторной установки скрытого состояния fromTo. Динамическое промо пересчитывает свои tween-значения отдельно.

## Контракты, которые нельзя потерять

| Сценарий | Требование |
|---|---|
| Mobile секции 2–3 | Обе находятся в обычном document flow. Нельзя перемещать вторую JS-transform внутри fixed-слоя, когда третья скроллится нативно: возникает рассинхрон на compositor-кадрах. Закреплено только промо, pinSpacing:false. |
| Mobile пороги | Внешние карточки и вложенные ряды используют общую линию 95%; промо сохраняет отдельный start под шапкой 56 px. |
| Вложенные карточки | Desktop ждёт 30% родителя; mobile дополнительно ждёт видимости самого ряда. Layout-offsetы ряда измеряются без влияния transform родителя. |
| Boost swipe | Горизонтальным transform/scale/alpha владеет внешний элемент; entrance — внутренняя поверхность. |
| Duration swipe | Native scrollLeft ряда и entrance внутренней поверхности независимы. Один жест — один фиксированный переход; swipe не меняет выбранный radio. |
| Connect tabs | Crossfade и мобильная высота используют одну обратимую timeline. Нельзя запускать конфликтующие tweens при частом переключении. Скрытая панель inert и aria-hidden. |
| Reverse | Внешний entrance проигрывается обратно выше порога; nested сбрасывается и повторно входит. Фокус внутри сохраняет соответствующую карточку видимой. Scroll-linked промо следует скроллу в обе стороны. |
| Клавиатура | Entrance меняет opacity, не visibility: Tab не пропускает карточки. Фокус сразу завершает родительский и соответствующий вложенный вход. Неактивные Connect-панели по-прежнему inert. |
| CSS-состояние entrance | Начальное скрытие задаёт общий GSAP-примитив. Дополнительное `visibility: hidden` в CSS оставит карточку невидимой даже при opacity 1. |
| Якоря | Первый переход по hash выполняется после mount/fonts/refresh; reload/back не перезаписывают сохранённую позицию. Пользовательский ввод отменяет отложенный переход. |
| Reduced motion | Нет pin, scrub, entrance и hover zoom; взаимодействия остаются доступны, переходы мгновенные. |

## Регрессионная проверка

В репозитории хранится воспроизводимый [Playwright-набор](../tests/README.md). После `npm ci` и `npx playwright install chromium` команда `npm run qa` запускает отдельный dev-сервер, выполняет проверки и сохраняет HTML-отчёт. При ошибке остаются screenshot и trace. TypeScript и production-сборка проверяются отдельно: `npm run typecheck`, `npm run build`.

## Что интегрирует продуктовая команда

- Бизнес-действия CTA, авторизацию, меню, ссылки, полный FAQ и аналитику. Демо не отправляет заявки и не выполняет подключение услуги.
- Реальную адаптивную верстку и планшетный сценарий, когда будет утверждён дизайн.
- Собственный asset pipeline: исходные PNG сохранены для точного визуального референса; для production нужны responsive-размеры, формат и бюджет загрузки.
- Общий bootstrap GSAP/Lenis, SSR-границы и cleanup согласно архитектуре продукта.
- Приёмку на физических iPhone/Safari, Android/Chrome и desktop-браузерах. Автоматизированная touch-эмуляция не заменяет аппаратную проверку.

Точные начальные/конечные значения, длительности, easing, селекторы и сценарии проверки приведены в единой [моушн-системе](MOTION_SYSTEM.md).
