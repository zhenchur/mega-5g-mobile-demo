# Аудит перед передачей разработчикам

Дата: **4 сентября 2026**. Область: актуальные desktop и mobile, общие motion-параметры и production-сборка для GitHub Pages.

**Результат:** в проверенных сценариях существенных motion-дефектов не обнаружено. Демо и спецификация готовы как референс поведения. Проверка выполнена в Microsoft Edge / Chromium headless с настоящими синтезированными touch/pointer/wheel-событиями; физические устройства и Safari не подключались.

## Исправления и решения, вошедшие в эту передачу

1. Мобильные входные пороги сведены к95%высоты viewport. Desktop-пороги сохранены.
2. Общий reveal вынесен из desktop-модуля в `src/motion/cardReveal.ts`; обе версии используют одну реализацию и общие nested-параметры.
3. У мобильной второй секции убрано JS-перемещение внутри fixed stage. Она и профили скроллятся нативно; закреплено только промо. Это устраняет выявленный рассинхрон скоростей.
4. Вложенные мобильные карточки ждут появления своего ряда, поэтому не заканчивают entrance за пределами экрана. Swipe и entrance разведены по слоям.
5. В HTML preload старого изображения промо заменён на используемое обеими версиями. Добавлен favicon, устранён лишний404.
6. README и интеграционная документация обновлены: прежние Product stack, тарифы и старые mobile-компоненты больше не выдаются за текущий сценарий.

## Границы и оставшаяся приёмка в продукте

- **Физический iPhone / Safari, Android и macOS Safari не проверены.** На устройстве нужно проверить инерцию и изменение browser bars; уже выполненная touch-эмуляция этого не заменяет.
- Планшет768–1279px намеренно показывает заглушку. Это отсутствие утверждённого сценария, а не дефект анимации.
- FAQ демонстрирует entrance четырёх строк; первая постоянно раскрыта, остальные отключены. Accordion-анимации в передаваемой системе нет.
- Заказ услуги, авторизация, меню, внешние переходы и большинство footer-ссылок — заглушки. Не принимать их за продуктовую реализацию.
- Исходные растры сохранены для точного визуального референса. Оптимизация responsive-ассетов, бюджет загрузки и испытание на слабых устройствах относятся к продуктовой интеграции.
- Демо не фиксирует длительность native smooth scrolling длительностей: её выбирает браузер. Точная заданная длительность есть у GSAP boost, crossfade и entrance.

Полный порядок сценариев для приёмки реализации приведён в [разделе12 моушн-системы](MOTION_SYSTEM.md#12-сценарии-приемки-при-переносе).
