# Мега 5G — общая motion-система

Версия: 5 сентября 2026. Область: текущие desktop и mobile. Документ описывает поведение демо и параметры, которые нужно воспроизвести в продуктовой реализации. Состояние проверок и публикации фиксируется отдельно в [HANDOFF_REVIEW.md](HANDOFF_REVIEW.md).

## 1. Быстрый ориентир

1. **У крупных карточек одна пластика:** подъем 120 px, поворот из −68° по X, глубина −36 px и проявление за 0.84 s с `power3.out`.
2. **Мобильная линия входа — 95% высоты viewport от верхнего края**, то есть на 5% выше нижнего края. Это `top 95%`, а не уменьшение длительности или амплитуды на 95%. На экране высотой 844 CSS px линия находится на y = 801.8 px. Высота фиксированной шапки из этого расчета не вычитается.
3. Desktop сохраняет линию 85% для профилей, Connect и FAQ. Две technology-карточки desktop входят у нижнего края viewport, со сдвигом старта второй на 0.06 s. Mobile technology-карточки входят независимо на общей линии 95%.
4. **Промо связано с прокруткой, вход карточек — со временем.** Промо следует за scroll в обе стороны. После пересечения линии карточка проигрывает вход за заданные секунды и заканчивает его даже при остановке scroll.
5. **Вложенные карточки — отдельный слой:** подъем 32 px и проявление за 0.84 s, шаг последовательности 0.08 s. Desktop ждет 30% входа родителя; mobile дополнительно ждет появления самого ряда на линии 95%.
6. **Секция 2 на mobile движется нативным scroll вместе с секцией 3.** Pin применяется только к промо. Единый нативный поток сохраняет синхронность секций при инерционном scroll на iOS.
7. **Смена состояния не перезапускает вход:** swipe, radio-выбор и Connect tabs имеют собственные механики. Обратный scroll может подготовить entrance к повторному запуску.
8. При `prefers-reduced-motion: reduce` вход и scroll-трансформации отсутствуют, интерактивные переключения мгновенные. Контент и управление остаются доступны.

Демо является референсом анимации. Продуктовая команда сохраняет эти параметры, порядок событий, области воздействия и доступность, адаптируя структуру и стили к своей дизайн-системе. Фиксированные размеры демо и тестовые ссылки не являются бизнес-контрактом.

## 3. Словарь и параметры

`Slot` — неподвижный элемент, занимающий место в layout и задающий порог входа. `Rise` — вложенный слой вертикального перемещения. `Card` — визуальная поверхность с 3D-поворотом и прозрачностью. `Nested` — маленькие карточки внутри родителя. `Scrub` — прогресс, непосредственно зависящий от scroll; `entrance` — вход с длительностью в секундах.

Все расстояния — CSS px, длительности — секунды, углы — градусы. В промо используются нормированные позиции timeline; они не означают секунды наблюдаемого эффекта.

| Параметр | Значение | Владелец / область |
|---|---:|---|
| `CARD_REVEAL_RISE` | 120 | Общий rise крупных карточек |
| `CARD_REVEAL_TIMING.duration` | 0.84 | Крупные и вложенные входы |
| `CARD_REVEAL_TIMING.ease` | `power3.out` | Крупные и вложенные входы |
| Начальные `rotationX / z / opacity` | −68 / −36 / 0 | Визуальная поверхность крупной карточки |
| Конечные `rotationX / z / opacity` | 0 / 0 / 1 | Та же поверхность |
| `transformPerspective` | 900 | Общий helper входа |
| `transformOrigin` крупной карточки | `50% 0%` | Поворот от верхнего края |
| `NESTED_CARD_REVEAL.rise` | 32 | Маленькие карточки |
| `NESTED_CARD_REVEAL.stagger` | 0.08 | Интервал старта соседних маленьких карточек |
| `NESTED_CARD_REVEAL.parentProgress` | 0.3 | Минимальный прогресс входа родителя |
| `MOBILE_CARD_REVEAL_VIEWPORT_RATIO` | 0.95 | Все mobile entrances, включая проверку ряда nested |
| `DESKTOP_CARD_REVEAL_VIEWPORT_RATIO` | 0.85 | Desktop профили, Connect, FAQ |
| Desktop technology stagger | 0.06 | Две карточки одного ряда |
| Конечный масштаб промо | 0.88 | Обе версии |
| Desktop подъем промо | −48 | Только desktop |
| Connect crossfade | 0.32, `power1.inOut` | Обе версии |
| Desktop zoom иллюстрации | 1 → 1.04, 0.42 | CSS `cubic-bezier(0.22, 1, 0.36, 1)` |
| Mobile boost-перелистывание | 0.52, `power3.out` | Отдельная GSAP-анимация свайпа |
| Определение оси жеста | 10 | Обе mobile-галереи |
| Порог переключения свайпом | 24 | Обе mobile-галереи |
| Шаг глубины boost-стопки | 8 | Только boost |

Вход использует `opacity`, сохраняя элементы в порядке Tab. При фокусе внутри карточки её вход сразу завершается; пока фокус остаётся внутри, reverse не скрывает управление. До начала входа указатель блокируется через `pointer-events`. `autoAlpha` (opacity и visibility) остаётся у crossfade неактивных панелей и у отдельных визуальных переходов. Общий helper задает `will-change` на время входа и очищает это свойство при завершении. Для 3D применяется `transformPerspective` на самой карточке; добавленная CSS `perspective` на родительском rise изменила бы итоговую пластику.

Начальное скрытие внешних карточек задаёт этот helper; дополнительного `visibility: hidden` в CSS нет. Значения entrance постоянны, поэтому `createCardReveal` отключает `invalidateOnRefresh` для своих tweens. ScrollTrigger по-прежнему пересчитывает геометрию start/end при refresh. Это сохраняет видимость и конечный transform сфокусированной карточки после смены reduced motion и resize. Динамические значения scroll-промо пересчитываются своим сценарием.

## 5. Общий вход крупной карточки

```text
slot                         ← измерение позиции / ScrollTrigger
└── rise                     ← y: 120 → 0
    └── card                 ← rotationX: −68 → 0, z: −36 → 0, opacity: 0 → 1
        └── content          ← статичное содержимое
```

Оба tween стартуют одновременно, длятся 0.84 s и используют `power3.out`. У helper нет дополнительного scale крупной карточки. Значение perspective остается 900 и в конце входа; поворот и z становятся нулевыми.

Для обычного slot используется `start: 'top 95%'` на mobile и `start: 'top 85%'` на desktop. Это пересечение верхней границей **исходного layout-slot** заданной линии viewport. Визуальный верх движущейся карточки из-за подъема и поворота может находиться ниже этой линии.

У всех этих entrances `invalidateOnRefresh: false`, `toggleActions: 'play none none reverse'`. Статические tween-значения сохраняются, а start/end пересчитываются при refresh:

| Событие | Результат |
|---|---|
| Вход вниз через start | Timeline играет вперед с текущей позиции |
| Остановка scroll после start | Вход заканчивается по времени |
| Дальнейшая прокрутка вниз | Видимая карточка остается в конечном состоянии |
| Прокрутка вверх, но еще ниже start | Карточка остается видимой |
| Возврат выше start | Timeline играет назад с текущего прогресса, если внутри нет фокуса |
| Фокус внутри входящей карточки | Вход сразу завершается; reverse не скрывает активное управление |
| Уход фокуса выше start | Отложенный reverse и сброс nested выполняются; следующий вход повторяет stagger |
| Быстрый разворот вниз во время reverse | Играет вперед с текущего прогресса |
| Новая загрузка с восстановленным scroll | Геометрия и пороги рассчитываются для текущего положения |

Нельзя использовать вращаемую карточку как источник геометрии собственного триггера. Это может создать обратное пересечение порога во время entrance и мерцание даже при неподвижном scroll.

Desktop technology-ряд использует этот же helper с двумя items и `stagger: 0.06`. Вход всего ряда заканчивается через 0.90 s. На mobile каждая technology-карточка получает свой независимый slot, поэтому дополнительного группового stagger между ними нет.

## 6. Промо и стык секций 1–3

### Общая визуальная последовательность

Сразу после загрузки промо видно полностью; загрузочного fade/entrance нет. При движении вниз белая секция «Как работает ускорение» перекрывает промо. Изображение, копирайт и CTA уменьшаются вместе вокруг `50% 50%`. Хлебные крошки не входят в масштабируемую группу.

| Нормированный прогресс промо | Действие |
|---:|---|
| 0 | Scale = 1; desktop y = 0; mobile без y |
| 0–0.04 | Контент сохраняет начальное состояние |
| 0.04–0.72 | Scale 1 → 0.88 с `power1.in`; desktop одновременно y 0 → −48 |
| 0.72–1 | Контент сохраняет конечное состояние, перекрытие продолжается |
| 1 | Промо закрыто следующей секцией |

`duration: 0.68` у tween промо и позиция `0.04` — доли полного диапазона scroll, поскольку основная timeline имеет длину 1 и `scrub: true`. Фактическая длительность зависит от действий пользователя. Opacity промо не анимируется.

### Desktop

Источники: `DesktopIntro` и его CSS.

- Pin всей intro-stage начинается с `top top`.
- Длина scroll-участка: `travel = hero.offsetTop + hero.offsetHeight`. Это включает отступ под шапку. Расстояние вычисляется из геометрии, не привязано к высоте viewport.
- Stage содержит hero и белую surface. Surface перемещается от `y = travel` к `y = 0` линейно на всем диапазоне. `pinSpacing: true` добавляет равный travel участок и сохраняет стык с профилями.
- `scrub: true` не добавляет временного отставания поверх Lenis. Числовой scrub-delay здесь изменил бы скорость поверхности относительно обычного потока профилей.
- Ширина белой поверхности постоянна: нет scaleX, расширения или анимации верхних углов. Нижние углы сохраняются, 32 px.
- Фоновая подложка hero обрезается снизу синхронно с подъемом surface через `--desktop-hero-underlay-clip` от 0 до travel.
- Technology entrance начинается, когда исходный верх grid доходит до нижней границы viewport. Формула учитывает pin-start, travel и положение grid внутри surface. Отрицательный start при уже видимом ряде не обнуляется, чтобы не ждать первого scroll.

### Mobile

Источники: `MobileIntro` и его CSS.

```text
intro
├── stage                     ← pinned только промо
│   └── hero
│       ├── breadcrumbs
│       └── content            ← только scale
└── benefits                  ← секция 2, обычный поток
profiles                      ← секция 3, обычный поток
```

- Pin stage начинается с `top 56px`, под фиксированной шапкой.
- Длина scroll-участка равна `hero.offsetHeight`; `pinSpacing: false`. Место stage в обычном layout сохраняется, дополнительный spacer-travel не добавляется.
- **Benefits не pinned, не translate и не scale.** Benefits и profiles имеют один нативный источник прокрутки и примыкают друг к другу независимо от JS-кадров.
- Масштабируется только `heroContent`, y не анимируется. Обычный scroll подводит белую поверхность поверх pinned промо.
- Промо и его фоновая подложка обрезаются снизу через `--mf-mobile-hero-underlay-clip: 0% → 100%`. Это исключает просвечивание промо под нижними скруглениями белой секции, 20 px.
- `scrub: true`, `invalidateOnRefresh: true`; конечное расстояние пересчитывается по текущей высоте hero.
- Смена мобильных порогов на 95% не меняет `top 56px`, длину pin или шкалу прогресса промо.

Ширина второй секции постоянна в обеих версиях. Mobile сохраняет обычное движение секции 2 в document flow: нативный iOS scroll может отображаться раньше следующего JS-кадра, поэтому перемещение всей секции через JS-transform нарушило бы синхронность стыка.

## 7. Вложенные карточки

В каждом из двух родителей — boost и «Мегаскорость» — три вложенных элемента. У них отдельная paused timeline. Каждый элемент получает `y: 32 → 0`, `opacity: 0 → 1`, 0.84 s, `power3.out`; последовательные старты: 0, 0.08 и 0.16 s. Полная последовательность от ее запуска занимает 1.00 s и не удлиняет родительскую timeline.

| Условие / событие | Desktop | Mobile |
|---|---|---|
| Разрешение запуска | Родитель идет вперед и его progress ≥ 0.3 | То же плюс layout-верх ряда достиг линии 95% |
| Самый ранний запуск | Через 0.252 s после старта родителя при непрерывном проигрывании с нуля | Через 0.252 s либо позже, когда ряд дойдет до линии |
| Верх ряда еще вне экрана | Отдельного условия нет | Мини-карточки ждут, даже если родитель уже появился |
| Повторный callback во время входа | Не перезапускает последовательность | Не перезапускает последовательность |
| Родитель уходит назад выше своего start | Мгновенный `pause(0)` вложенного входа | Мгновенный `pause(0)` вложенного входа |
| Сам ряд уходит назад выше своей линии | Отдельного row-trigger нет | Мгновенный сброс; при следующем входе возможен повтор |
| Swipe или смена radio | Не относятся к entrance | Не сбрасывают nested timeline |

`progress ≥ 0.3` означает долю времени родительской timeline, а не 30% пройденного пиксельного расстояния. `power3.out` распределяет движение неравномерно.

На mobile отдельный row-trigger привязан к неподвижному родительскому slot, а позиция ряда вычисляется суммой layout-`offsetTop` по `offsetParent` минус `window.innerHeight × 0.95`. `getBoundingClientRect()` движущегося вложенного ряда для этого условия не используется. Иначе 3D-поворот родителя мог бы сдвигать собственный порог вложенных элементов.

Слои mobile-галерей:

```text
крупный slot → rise → card
└── viewport / fieldset       ← layout и область жеста
    └── item / label          ← boost x/scale/alpha ИЛИ позиция scrollLeft
        └── item-rise         ← только nested y/opacity + фон и содержимое
```

Фон и все содержимое маленькой карточки находятся на ее внутреннем rise. Внешняя оболочка сохраняет ширину, gap, `offsetLeft`, radio-семантику и вычисления свайпа. Нельзя давать nested entrance и swipe одним и тем же GSAP-target: `killTweensOf()` при перелистывании уничтожил бы вход, а параллельные transform/opacity перезаписывали бы друг друга.

## 8. Галереи и выбор длительности

### Mobile: дополнительное ускорение

Источник: `useStackSwipe`, цель — `.mf-mobile-boost__item`.

- Три карточки, два положения, без зацикливания; начальная страница 0. На первом положении доступны карточки 1–2, на втором 2–3. Уходящая первая карточка образует видимую подложку стопки.
- Swipe, нажатие точки и стрелки клавиатуры используют одну функцию `goToPage`. `Home` выбирает первое, `End` — второе положение.
- При горизонтальном жесте ось фиксируется после 10 px. После достижения 24 px выполняется ровно один переход за жест. Карточки не следуют непрерывно за пальцем.
- Анимация длится 0.52 s с `power3.out`. При быстром противоположном действии текущие tweens останавливаются; новый идет от текущего визуального положения.
- Шаг ряда `S = computed card width + computed columnGap`. CSS gap равен 6 px; измерять нужно layout-ширину, не масштабированный bounding rect.
- Для позиции 1 x первой карточки равен −8 px, второй и третьей — −S. Первая уменьшается до 0.94, получает alpha 0.5. Во второй и третьей scale = 1, alpha = 1. Для позиции 0 все x = 0, scale = 1, alpha = 1.
- `ResizeObserver` пересчитывает S и мгновенно устанавливает текущую логическую страницу в новой геометрии.
- Скрытые для чтения слайды получают `aria-hidden`; точки — `aria-pressed`, изменение положения объявляется через один `aria-live="polite"` status.

### Mobile: 6 / 12 / 24 часа

Источник: `useHorizontalSlider`, область — `.mf-mobile-profile__durations`, элементы — `.mf-mobile-duration`.

- Это обычный горизонтальный ряд без scale/alpha во время перелистывания. Nested entrance внутренней поверхности — отдельный эффект.
- Swipe пошаговый: один горизонтальный жест ≥24 px переводит ряд в ближайшую следующую отличающуюся позицию. Длина жеста после порога не увеличивает перемещение. На границе ряд останавливается, зацикливания нет.
- Tap выбирает radio и вызывает переход к тому же рассчитанному положению. Swipe двигает ряд, **не меняет выбранную длительность**.
- Целевая позиция: `clamp(card.offsetLeft − viewport.paddingLeft, 0, scrollWidth − clientWidth)`. Разные карточки могут иметь одинаковую конечную позицию; шаг пропускает такие дубликаты.
- Переход выполняется нативным `scrollTo({ behavior: 'smooth' })`. Длительность и кривая задаются браузером; фиксированного значения в миллисекундах у этого эффекта нет. В reduce — `instant`.
- В демо ширина карточки 118 px, gap 8 px; viewport выходит до обеих границ темного родителя, сохраняя внутренние поля 16 px. Например, при ширине страницы 360 px позиции ряда — 0 и 74 px. Это результат геометрии, а не жестко заданный шаг.
- Для быстрых обратных действий используется логический целевой индекс, а не промежуточный `scrollLeft`.
- Radio сохраняет нативное управление стрелками; `Home` / `End` выбирают первую / последнюю длительность и прокручивают к ней. Программный focus выполняется с `preventScroll: true`, чтобы браузер не делал дополнительный скачок перед smooth scroll.

На desktop все длительности видны в одном ряду и используют radio-выбор без slider. Начально выбрано «6 часов» в обеих версиях. Цвет фона, радиоиндикатор и текстовое состояние обновляются при выборе без отдельной GSAP-анимации.

### Общий контракт жестов

Обе мобильные области сохраняют `touch-action: pan-y pinch-zoom`: вертикальный жест прокручивает страницу, масштабирование страницы остается доступным. Горизонтальный жест подавляет следующий синтетический click, чтобы отпускание после свайпа не выбирало карточку. Новое нажатие сбрасывает подавление; клавиатурный click проходит.

Boost поддерживает touch-события и pointer для остальных устройств, избегая двойной обработки touch. Длительности используют Pointer Events. При переносе нужно сохранить завершение жеста по финальным координатам `pointerup` / `touchend`, отмену при cancel и обработку перехода implicit pointer capture с label на viewport. Общий `bindStepSwipe` отслеживает завершение и движение на document, включая выход за границы ряда до фиксации оси. Потеря кнопки мыши, blur окна, скрытие страницы, cancel/capture loss и второе касание отменяют жест. После отпускания hover не может вызвать переключение. Оба адаптера удаляют listeners и observers при unmount.

## 9. Connect: вход и вкладки

Начальное состояние обеих версий — «Я новый абонент». Вторая вкладка — «Я клиент МегаФона».

| Параметр | Desktop | Mobile |
|---|---|---|
| Область viewport-entrance | Две вложенные иллюстрации синхронно, одним helper | Вся внешняя карточка, включая изображение, текст, шаги и CTA |
| Trigger | Неподвижный контейнер панелей, 85% | Неподвижный reveal-slot, 95% |
| Заголовок секции и tabs | Не анимируются входом | Не анимируются входом |
| Переключение панелей | Одновременный crossfade | Одновременный crossfade + высота контейнера |
| Duration / ease | 0.32 / `power1.inOut` | 0.32 / `power1.inOut` |
| Геометрия | Обе панели в grid-стопке, размер секции постоянен | Высота интерполируется между `offsetHeight` двух панелей |
| Повторный выбор текущей вкладки | Без нового действия | Без нового действия |
| Быстрое переключение назад | Reverse того же timeline с текущей позиции | Reverse той же timeline прозрачности и высоты |
| Scroll reverse | Возвращает иллюстрации в начало entrance | Возвращает всю карточку в начало entrance |
| Tab click после entrance | Только crossfade | Только crossfade и высота |

Панели crossfade имеют противоположные значения `autoAlpha`, начинают tween в одной позиции 0; сумма opacity во время обычного перехода остается равной 1. Переключение не включает отдельный translate/scale или последовательный fade-out → fade-in.

На mobile в `ResizeObserver` измеряются **внутренние панели**, а не анимируемый контейнер. При изменении размеров timeline инвалидируется с сохранением текущего прогресса. После завершения forward/reverse и после изменения размеров планируется `ScrollTrigger.refresh()` в RAF, чтобы обновить пороги следующих секций. Наблюдение за самой интерполируемой высотой создало бы цикл resize-обработки.

У tabs роли `tablist` / `tab` / `tabpanel`, связи `aria-controls` и `aria-labelledby`. Только активный tab находится в обычном Tab-порядке. Стрелки Left/Right переключают между двумя вкладками; Home/End выбирают крайние. Семантическое активное состояние меняется сразу по действию пользователя; неактивная панель получает `inert` и `aria-hidden`, даже пока еще видна часть crossfade. Ее элементы не должны принимать focus и pointer.

## 10. Дополнительные состояния и статичные зоны

Desktop иллюстрации трех месячных профилей и «Мегаскорости» увеличиваются до 1.04 при hover по кнопкам действий карточки или `:focus-visible` на этих кнопках. Hover требует `(hover: hover) and (pointer: fine)`. Длительность 420 ms, CSS-кривая `cubic-bezier(0.22, 1, 0.36, 1)`, origin в центре. При уходе hover/focus иллюстрация возвращается к 1 по той же transition. Hover по всей поверхности карточки сам по себе не является триггером.

FAQ демонстрирует вход четырех строк. Первая строка постоянно раскрыта; остальные три кнопки disabled. Анимация accordion height, смена открытого вопроса и поворот стрелок по клику в демо отсутствуют.

Самостоятельного entrance нет у заголовков секций, fixed header, навигации и footer. У контента внутри крупной карточки есть движение родителя, даже если собственной timeline у элемента нет. Нет автопрокрутки каруселей, бесконечных циклов и фоновых idle-анимаций.

Границы демонстрационной интерактивности:

- Hero ведет к профилям (`#desktop-profiles` / `#profiles`). Mobile-кнопки подключения профиля ведут к `#connect`.
- Desktop-кнопки подключения/подробностей профиля не реализуют заказ. Mobile-кнопки подробностей отмечены `aria-disabled`.
- CTA обеих Connect-панелей пока ведут на тот же Connect-якорь. Переход в приложение, личный кабинет и оформление SIM не реализованы.
- Шапка и footer содержат демонстрационные элементы/ссылки; их бизнес-поведение не задано motion-системой.

## 11. Reduced motion, прокрутка и жизненный цикл

| Режим / изменение | Ожидаемый контракт |
|---|---|
| Reduce при загрузке | Нет pin/scrub, 3D-входов, nested-входов и desktop hover zoom; статичный контент видим |
| Connect в reduce | Выбранная панель и ее высота устанавливаются мгновенно |
| Boost в reduce | Сохраняется конечная раскладка выбранной страницы, переход к ней мгновенный |
| Длительности в reduce | Выбор сохранен; горизонтальный переход `instant` |
| Включение reduce во время entrance | GSAP media context возвращает исходные видимые стили и снимает pin |
| Включение reduce во время Connect crossfade | Новая media-ветка устанавливает уже выбранную вкладку в ее конечное состояние |
| Возврат к обычному motion | Media contexts создаются заново для текущего layout и scroll |
| Переход между mobile/tablet/desktop | Старое дерево, timelines, pin, listeners и observers очищаются; новая версия монтируется отдельно |
| Изменение размера внутри mobile | Пересчитываются scroll-пороги и геометрия слайдеров; текущая логическая страница сохраняется |

Desktop Lenis работает в window-режиме, без `scrollerProxy`: `autoRaf: false`, `lerp: 0.1`, `smoothWheel: true`, `respectReducedMotion: true`, `stopInertiaOnNavigate: true`. Его `raf` вызывается единым `gsap.ticker`, событие scroll вызывает `ScrollTrigger.update`. Touch-инерция отдельно не синхронизируется. Локальные hash-ссылки обрабатываются через `lenis.scrollTo`; сочетания клавиш и модифицированные клики не перехватываются. В reduce Lenis уважает системную настройку прокрутки.

Mobile использует scroll окна без Lenis и без глобального перехвата вертикальных жестов. Это критично для естественного iOS-поведения и синхронности стыка секций 2–3.

Анимации создаются внутри `useGSAP` и `gsap.matchMedia`, а выбор диапазона — в `App`. React работает в StrictMode, поэтому двойной цикл setup/cleanup в разработке не должен оставлять старые triggers. Event-created tweens boost привязаны к его собственному media context. Cleanup отключает observers, удаляет listeners, отменяет RAF и освобождает pointer capture. Desktop дополнительно удаляет ticker callback, уничтожает Lenis и восстанавливает GSAP lag smoothing.

В mobile intro после `document.fonts.ready` выполняется refresh с проверкой, что компонент не размонтирован. Новая продуктовая реализация должна также обновлять измерения после своих изменений геометрии. Вызов `ScrollTrigger.refresh()` на каждом scroll-кадре не является частью сценария.

Свежая ссылка с `#profiles` / `#connect` на mobile или `#desktop-profiles` / `#desktop-connect` на desktop разрешается после mount, готовности шрифтов и refresh геометрии. Reload и back/forward сохраняют нативное восстановление позиции. Пользовательский ввод до завершения подготовки отменяет отложенный переход.

## 12. Сценарии приемки при переносе

Эта таблица задает ожидаемое поведение, а не подтверждает прохождение проверок. Фактические результаты, браузеры и ограничения см. в [HANDOFF_REVIEW.md](HANDOFF_REVIEW.md).

| Сценарий | Что проверить |
|---|---|
| Первый экран, без scroll | Промо сразу видно. Уже попавшие в линию входа карточки не требуют искусственного первого scroll |
| Медленный scroll вниз через промо | Контент scale до 0.88; mobile y отсутствует; desktop y до −48; белая секция постоянной ширины |
| Быстрый scroll и инерция через секции 2–3 | На mobile обе секции движутся одним потоком, без щели, разной скорости и рывка при конце pin |
| Обратный scroll через промо | Scale и desktop y возвращаются по тому же scroll-progress; неподвижная шапка остается сверху |
| Остановка на ±2 px от входной линии | Нет самопроизвольного reverse/мерцания. Геометрия slot не зависит от поворота карточки |
| Вход parent с остановкой scroll | За 0.84 s карточка достигает конечного положения |
| Tall mobile-карточка, ряд еще ниже экрана | Parent входит; nested ждет собственной линии 95% |
| Повторный вход nested | Выход ряда/родителя назад сбрасывает маленькие карточки; повторный вход запускает последовательность 0 / 0.08 / 0.16 s |
| Boost во время/после entrance | Свайп и точки не обрывают nested y; два фиксированных положения, быстрый разворот без скачка |
| Длительности: короткий и длинный swipe | Жест <24 px не переключает; ≥24 px выполняет один шаг, не меняет radio |
| Длительности: tap и keyboard | Выбор меняется, ряд доезжает к рассчитанной позиции без мгновенного скачка фокуса |
| Вертикальный жест поверх обоих рядов | Страница прокручивается; горизонтальный click не возникает случайно |
| Connect: вперед/назад и быстрые клики | Один непрерывный crossfade; mobile-высота меняется тем же playhead, desktop-высота постоянна |
| Connect: Tab/Left/Right/Home/End | Активный tab и panel согласованы, скрытая панель не принимает focus |
| FAQ / footer | Видимы; у FAQ только entrance, footer статичен |
| Live reduce посреди движения | Контент видим, выбранные состояния доступны, старые pin/entrance стили очищены |
| Фокус в radio → scroll вверх → reduce/normal → resize → возврат | Parent и nested видимы, rise/rotation/z в конечном состоянии; blur выше порога снова разрешает reset/replay |
| Desktop технологии при обычном motion | Обе карточки видимы после входа: проверять opacity вместе с visibility и родительскими стилями |
| Resize и browser bars | После измерения пороги актуальны; mobile стык не получает JS-перемещения, галереи сохраняют логическое состояние |
| Границы 767↔768 и 1279↔1280 | Одна версия, без дублирующихся GSAP triggers и Lenis |
| Свежая deep link / reload после ухода от якоря | Первый переход ставит секцию под шапку; reload сохраняет последнюю позицию пользователя |
| Tab с первого экрана до профилей и radio | Управление не пропускается; родитель и вложенная поверхность сразу видимы при фокусе |
| Отпускание мыши вне ряда до фиксации оси | Возврат курсора без нажатия не листает галерею |
| Connect customer: ширина 390 → 320 | Высота контейнера совпадает с новой высотой активной панели |
| Опубликованный GitHub Pages subpath | Загружаются JS, CSS, шрифты и изображения; якоря и оба диапазона работают |

Для браузерной проверки нужны мобильные ширины 320, 360, 390 и 767 px, desktop 1280 и 1440 px, промежуточный диапазон и разные высоты viewport. Прокрутку проверяют в движении и при резком развороте, а не только после остановки. Проверка в Chromium с touch-эмуляцией не подтверждает результат на физическом iPhone; Safari/iOS с изменением browser bars — отдельный контроль.

## 13. Порядок интеграции

1. Собрать статичный layout, доступные tabs/radio/карусели и reduced-motion состояние. Проверить порядок секций и единый scroll-container окна.
2. Добавить отдельные неподвижные slots и вложенные motion-слои. Перенести общий `createCardReveal` с токенами; подключить mobile 95% и desktop 85% как явные варианты.
3. Подключить независимые entrances крупных карточек, затем nested gating и stagger. Проверить остановку на пороге и обратный вход.
4. Собрать промо с разной архитектурой pin для desktop/mobile. Сохранить нативный поток второй и третьей mobile-секций, форму их стыка и общий scale hero.
5. Подключить интерактивные timelines отдельно от entrance: boost, duration slider и Connect crossfade. Сохранить управление клавиатурой и отсутствие конфликтов transform/opacity.
6. Подключить resize/font/content refresh и полную очистку. Проверить live reduced-motion и remount через диапазоны.
7. Сопоставить реализацию с демо по сценариям раздела 12 и зафиксировать реальный браузерный отчет. После интеграции бизнес-ссылок повторить anchor/focus и keyboard-сценарии.

У страницы нет единой master timeline. Система состоит из общего входного примитива и независимых сценариев с явными владельцами свойств: scroll-промо, time-based entrance, nested entrance, интерактивный crossfade, swipe и CSS hover. Это позволяет переносить механику по зонам без взаимного перезаписывания анимаций.
